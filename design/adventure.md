## 5. 冒险

### 5.1 冒险循环

- 输入表示尝试，不能直接决定成功或授予奖励。保留编号选项与自由行动，系统命令优先于剧情输入。
- 导航、查看、取消、保存不推进冒险。一次战斗及战后情境合计推进一个冒险回合；一次有效谈话在结束时推进一个；休息产生一次剧情更新。已结算行动不因返回界面、读档或重新生成叙述而重复执行。
- 情境逐步加入区域、在场 NPC 与可见敌人，行动不必换地点。新威胁优先可见，玩家可交谈、战斗或绕开。区域与已出现敌人的强度固定，不随玩家成长缩放。
- **选项兼顾玩家长项（v1，2026-10-14 确认）。** 情境选项里，若存在合理的、能发挥玩家最强技能的途径，应包含它，让窄专精的角色也能用自己的方式推进。必须克制，避免剧情和关卡显得刻意：
  - 只调整“呈现哪些选项”，不改变世界：不为玩家的长项新增或改写已叙述的事实、障碍、NPC 或难度；区域与挑战强度照旧固定。
  - 只在情境自然允许时出现，不要求每个情境都有；选项写成世界内的具体行动（如“趁守卫换岗翻过院墙”），不写“使用潜行 24”。
  - 选项不全部贴合长项，照常混入其他路线；玩家不擅长的局面也会出现，那正是队友、工具、知识与替代路线发挥作用的地方。自由行动始终可用。
- 伏击先限于普通单敌，逃跑或倒下后不立即再次伏击（§6.3）。场景规模候选：NPC、敌人各最多 3 个，先验证单敌。

### 5.2 地点与连接图

- 地点之间用连接图，局部战斗用网格，不同时维护两种战斗模式。
- 地点记录保存稳定 ID、名称、安全等级、已发现状态与战场布局；情境按 ID 引用地点。
- 首版做轻量连接图：玩家实际从 A 移动到 B 时自动记录连接；续写请求提供当前地点的已知相邻地点，LLM 返回已有 ID 或提议新地点，Java 校验已有 ID 确实相邻；“去已知相邻地点”作为不触发检定的导航选项。
- 图结构不保证地理一致性，以程序持有的身份、连接与状态为准。

### 5.3 休息

| 安全等级 | 恢复 | 打断 |
|---|---|---|
| 安全（城镇、旅店、营地） | 回满 | 无 |
| 一般野外 | 50% 最大 HP | 有一定概率 |
| 危险区域 | 50% 最大 HP | 概率更高 |

- 无在场敌人时可休息。安全等级只决定恢复量与打断概率，不决定遭遇密度或敌人难度；由 LLM 在创建地点时提出、Java 校验后保存，之后不变；打断由 Java 按等级掷骰。
- 被打断时先恢复应得量的一半，再以伏击开战（§6.3）。反复休息不设上限，每次消耗一个冒险回合、各自承担风险；刚逃跑或倒下后的下一次休息不会被打断。

### 5.4 对话（方向）

- 可与在场 NPC、未开战的敌人交谈；不会说话的敌人只表现反应。至少一次有效交流后，结束时合并谈话结果并更新情境；未交流直接返回不推进。
- 台词不直接改 HP、发物品、移除敌人或触发战斗；承诺与威胁通过结束后的结构化结果提出，由 Java 校验执行。
- NPC 先只有姓名、身份、态度、备注与近期对话，态度影响表演，不实现复杂心智。当前场景的角色资料存档，重要谈话结果进入历史；上下文保留本次谈话的关键经过（如早先的承诺）。
- 候选限长：输入 200 字符、回复 300、备注 120、NPC 显示名 24；近期 6 句配合本次谈话记录。
- 不做专门对话模式（2026-10-16 确认），由自由行动＋检定覆盖交谈；NPC 名字与台词在冒险叙述中高亮显示，之后再加点击 NPC 名字查看其信息（抽屉或弹窗）。

### 5.5 生成内容与挑战评估（方向）

- LLM 可提出新装备、特殊行动和敌人，但只能组合 Java 已支持的效果。名称与来历可开放生成；目标、参数、成本、持续时间与触发条件必须可校验、可执行。不承诺任意自然语言能力或自动平衡。
- 特殊行动获得时一次性生成与验证，使用时不调用模型。拒绝不可达成本、无界持续时间、无限资源循环与递归触发。无效奖励不授予并提示，可保留其他独立有效内容；影响情境一致性的错误则整份不提交。
- 能力评估关注输出、生存、目标覆盖、启动条件与准备程度，不只给单一战力分。先用两个构筑对比单敌与多敌，在状态副本上复用真实规则推演约 8 轮；无法判断时输出“不确定”。候选标签 Trivial／Easy／Fair／Hard／Deadly／Unknown。
- 新挑战可调整敌人组合与战斗间隔，保留区域与已有敌人的强度。风险过高时提供可见威胁与离开选择；内容不足时引导前往更危险区域，不靠无限堆敌补偿。

### 5.6 存档与连续性

- 每加入一个持久功能就同步补齐存读：属性、技能、未分配成长点、背景、特质及使用状态、知识与线索、已学特殊行动、物品与特殊行动定义、装备、敌人状态、角色资料、地点、奖励间隔与已结算标识。读档不调用模型，不重复领奖，也不重新解释已生成的效果。
- 战后叙述或倒下情景生成失败时，保存“已结算、待叙述”状态，读档只重新请求叙述，不重新结算；不得重复扣血、发奖或倒退事实，候选变化不半提交。
- 写入失败应保留原档；损坏槽位保持可见；旧格式明确提示不兼容。
- 长冒险的请求长度须限制，近期记录与持久摘要的策略待定。
