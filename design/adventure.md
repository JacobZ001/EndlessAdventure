# Endless Adventure 设计：冒险

本文件是 [DESIGN.md](../DESIGN.md) 的 §5，章节编号沿用总文档，文中“§X.Y”跨文件通用（各章所在文件见 DESIGN 的模块索引）。术语见 DESIGN 术语表，计划与实现现状见 DESIGN §2。

## 5. 冒险

### 5.1 冒险循环

- 输入表示尝试，不能直接决定成功或授予奖励。保留编号选项与自由行动，系统命令优先于剧情输入。
- 导航、查看、取消、保存不推进冒险。一次战斗及战后情境合计推进一个冒险回合；一次有效谈话在结束时推进一个；休息产生一次剧情更新。已结算行动不因返回界面、读档或重新生成叙述而重复执行。
- 情境逐步加入区域、在场 NPC 与可见敌人，行动不必换地点。新威胁优先可见，玩家可交谈、战斗或绕开。区域与已出现敌人的强度固定，不随玩家成长缩放。
- **选项兼顾玩家长项（v1，2026-10-14 确认）。** 情境选项里，若存在合理的、能发挥玩家最强技能的途径，应包含它，让窄专精的角色也能用自己的方式推进。必须克制，避免剧情和关卡显得刻意：
  - 只调整“呈现哪些选项”，不改变世界：不为玩家的长项新增或改写已叙述的事实、障碍、NPC 或难度；区域与挑战强度照旧固定。
  - 只在情境自然允许时出现，不要求每个情境都有；选项写成世界内的具体行动（如“趁守卫换岗翻过院墙”），不写“使用潜行 24”。
  - 选项不全部贴合长项，照常混入其他路线；玩家不擅长的局面也会出现，那正是队友、工具、知识与替代路线发挥作用的地方。自由行动始终可用。
- 伏击先限于普通单敌，逃跑或倒下后不立即再次伏击（§6.3）。场景规模候选：NPC、敌人各最多 3 个，先验证单敌。

### 5.2 地点与连接图

- 地点之间用连接图，局部战斗用网格，不同时维护两种战斗模式。
- 地点由 Java 持有，LLM 不能凭空瞬移或做不合逻辑的转场。
- 冒险的重心在野外与遗迹：聚落是补给、休息与接任务的中转站，不久留。

**三层结构（2026-11-13 确认）**

| 层 | 是什么 | 持有 |
|---|---|---|
| 区域 Region | 一片地貌 | 地貌、基础危险等级、威胁阵线（§5.7） |
| 地点 Location | 一组相关联的房间：一座城镇、一个遗迹、一处单独的野外景点；点图的节点 | 名称、种类、主题、危险等级 |
| 房间 Room | 地点里的一个可到达之处：城里的市场与酒馆、遗迹里的一间墓室、渡口本身 | 名称、场景图 |

- “房间”对应 Five Room Dungeon 与 Jaquaysing 的房间，户外的市场或渡口也叫房间，只是内部术语，不显示给玩家。
- 种类只有三种：聚落、野外、遗迹，决定安全等级（休息，§5.3）。某种机制需要新的区分时再加（如有了交易才加市场）。
- 危险等级是数值，决定敌人强度，属于区域与地点，与种类无关：两个遗迹难度不同是危险等级不同；地点可以比所在区域更危险（温和森林里的龙巢）。
- 主题是一句话（“被水淹没的地穴”），让同一地点的房间风格一致。

**v1 实现（2026-11-13 确认）**

- 区域层暂缓，整个世界视作一个隐含的区域。危险等级暂时只交给 LLM 参考（目前只有一种敌人）。
- Java 记录到过的地点与房间（ID 由 Java 分配）及房间之间的已知连接，进存档；游戏状态持有当前房间。
- 移动：原地不动；去已知的相邻房间；在当前地点内新建一个相连的房间（往遗迹深处走）；新建一个地点及它的第一个房间（离开城镇）。续写与战后（胜利、撤离、倒下，如被掳走）可以移动，休息不能；漏写视为不动。开场新建第一个地点，种类不限。不合法时整份续写不提交（§5.5）。
- 场景图：新建房间时 LLM 必须从所在地点种类的图库里选一张，之后固定，不出现无图。同一地点的房间只能靠名称与叙述保持主题一致。
- 已知的相邻房间作为导航选项，不触发检定（第二步）。
- 运行时生成场景图（提交后）：没有贴切的预设图时，先显示最接近的预设图，在后台线程请求图片 API、缩放裁剪到场景尺寸并按房间 ID 缓存，生成好后替换。现有管线是 Python，运行时这一段要用 Java 重做。

| 种类 | 安全等级 | 图库 |
|---|---|---|
| 聚落 | 安全 | village、town_gate、market、market_crowded、tavern、tavern_day、castle_hall |
| 野外 | 一般 | forest_path、deep_forest、grassland_road、river_ford、mountain_pass、snowfield、swamp、coast、camp |
| 遗迹 | 危险 | ruins、bandit_camp、ruined_watchtower、ruined_watchtower_underneath、cave、mine、crypt、dungeon、underground_hall、shrine、monster_lair、treasure_vault |

**遗迹与五房间结构（方向）**

- 遗迹是一个由多个房间组成的地点（如被强盗占据的矿坑），强度固定（§5.1）。
- 节奏参考 Five Room Dungeon：入口与守卫 → 谜题或角色扮演挑战 → 诡计或挫折 → 高潮（大战或冲突）→ 奖励、揭示或反转。进入遗迹时由 Java 排好约五个带角色的房间，LLM 按角色写情境；高潮房间放首领遭遇，奖励房间发战利品；走完后遗迹标为已清理，玩家回到中转站或继续上路。

### 5.3 休息

| 安全等级 | 恢复 | 打断 |
|---|---|---|
| 安全（聚落） | 回满 | 无 |
| 一般（野外） | 50% 最大 HP | 20% |
| 危险（遗迹） | 50% 最大 HP | 40% |

- 无在场敌人时可休息。安全等级只决定恢复量与打断概率，不决定遭遇密度或敌人难度，敌人强度由危险等级决定（§5.2）。两者正交：高阶地图里的城市安全但危险（城里能安心睡觉，城外的敌人很强），新手区的哥布林洞穴不安全但不危险（睡觉会被打扰，敌人很弱）；合成一个数值，高阶地图就没有安全的城镇（与 §5.7 的尺度升级冲突）。安全等级不另存，由种类推出；由地点种类决定（§5.2），打断由 Java 按等级掷骰（概率 2026-11-13 定为起点，试玩校准）。
- 被打断时先恢复应得量的一半，再由专门的请求生成必有敌人的情境；伏击的先手规则（§6.3）未实现前不强制开战，玩家照常可以战斗或设法避开。反复休息不设上限，每次消耗一个冒险回合、各自承担风险；刚逃跑或倒下后的下一次休息不会被打断。

### 5.4 对话（方向）

- 可与在场 NPC、未开战的敌人交谈；不会说话的敌人只表现反应。至少一次有效交流后，结束时合并谈话结果并更新情境；未交流直接返回不推进。
- 台词不直接改 HP、发物品、移除敌人或触发战斗；承诺与威胁通过结束后的结构化结果提出，由 Java 校验执行。
- NPC 先只有姓名、身份、态度、备注与近期对话，态度影响表演，不实现复杂心智。当前场景的角色资料存档，重要谈话结果进入历史；上下文保留本次谈话的关键经过（如早先的承诺）。
- 候选限长：输入 200 字符、回复 300、备注 120、NPC 显示名 24；近期 6 句配合本次谈话记录。
- 不做专门对话模式（2026-10-16 确认），由自由行动＋检定覆盖交谈；NPC 名字与台词在冒险叙述中高亮显示，之后再加点击 NPC 名字查看其信息（抽屉或弹窗）。

### 5.5 生成内容与挑战评估（方向）

- LLM 可提出新装备、特殊行动和敌人，但只能组合 Java 已支持的效果。名称与来历可开放生成；目标、参数、成本、持续时间与触发条件必须可校验、可执行。不承诺任意自然语言能力或自动平衡。
- 特殊行动获得时一次性生成与验证，使用时不调用模型。拒绝不可达成本、无界持续时间、无限资源循环与递归触发。无效奖励不授予并提示，可保留其他独立有效内容；影响情境一致性的错误则整份不提交。
- 能力评估关注输出、生存、目标覆盖、启动条件与准备程度，不只给单一战力分。先用两个构筑对比单敌与多敌，在状态副本上复用真实规则推演约 8 轮；无法判断时输出“不确定”。候选标签 Trivial／Easy／Fair／Hard／Deadly／Unknown。
- 新挑战可调整敌人组合与战斗间隔，保留区域与已有敌人的强度。风险过高时提供可见威胁与离开选择；内容不足时引导前往更危险区域，不靠无限堆敌补偿。

### 5.6 存档与连续性

- 每加入一个持久功能就同步补齐存读：属性、技能、未分配成长点、背景、特质及使用状态、知识与线索、已学特殊行动、物品与特殊行动定义、装备、敌人状态、角色资料、地点、奖励间隔与已结算标识。读档不调用模型，不重复领奖，也不重新解释已生成的效果。
- 战后叙述或倒下情景生成失败时，保存“已结算、待叙述”状态，读档只重新请求叙述，不重新结算；不得重复扣血、发奖或倒退事实，候选变化不半提交。
- 写入失败应保留原档；损坏槽位保持可见；旧格式明确提示不兼容。
- **记忆分层（方向，2026-11-13）。** 一场战役几十小时，远超模型上下文，须从一开始分层管理：
  - 正史状态：Java 持有的结构化事实（地点、NPC、阵线进度、线索、物品），每次结算时更新。
  - 近期原文：最近几个场景的完整文字，滚动窗口。
  - 分级摘要：小旅程 → 区域编年 → 纪元传说，在边界处（小旅程或遗迹结束、离开区域、纪元结束）写一次，不再改。
  - 检索：以 Java 推送为主，按结构挑出相关记录（当前地点、在场 NPC、进行中的线索、storylet 声明读取的状态），结果确定、好测试；常驻前缀只放很小的核心（世界设定、战役阵线摘要、当前区域骨架）；模型主动检索（function calling）留给推送覆盖不到的长尾，较晚再加，因为模型不知道自己缺什么。

### 5.7 终局愿景：地图与叙事结构（方向，2026-11-12）

不受课程期限约束的理想形态，也作为 Vestige 的参考。总原则：程序持有骨架（地点、连接、状态、威胁进度），LLM 写血肉（名字、文字、对话）。要避免的是 AI Dungeon 式漂移：没有目标，生成的地点像滚动窗口，去过的地方失去意义。

**空间：点图（pointcrawl）**

- 世界由区域组成，可在边缘生长。区域有地貌、危险等级（离中心城越远越高，参考 West Marches）、主导威胁或阵营，含 3–8 个地点。
- 地点是点图的节点，只收值得停留的地方（林中废弃的猎人小屋，而不是一片普通树林），记录名字、种类、状态与已发现的出口；地点内部由房间组成（§5.2）。
- 路是带属性的边：远近、危险、是否隐藏（听到传闻才知道）、通过条件（需要向导）。选路就是选风险与代价。
- 新建地点时的约束由区域决定：区域规定可出现哪些种类与主题的地点，区域之间规定如何过渡。
- 地标：地点可写明从这里能望见什么（东边山脊上的孤塔），指向未去过的地点或遗迹，本身就是方向选项（参考 Kevin Lynch 的城市意象与《旷野之息》的三角形法则）。

**遗迹（delve）**

- 一个由多个房间组成、强耦合的地点，不限地下：有起伏、遭遇和最终奖励。节奏按五房间编排（§5.2），形状参考 Jaquaysing：环路、第二入口、秘密，让走法本身也是选择。
- 内容由“主题 × 地形”决定可抽到的特征与危险（参考 Ironsworn，如闹鬼 × 矿坑）；深入程度用进度条表示；走完后改变区域状态（矿坑已肃清）。

**任务网（与地图正交）**

- 参考 Justin Alexander 的 node-based 设计：节点是情境（人、地点、组织、事件），节点之间由线索相连。地图回答“能去哪”，任务网回答“为什么去”。
- 必须找到的东西给多条线索（Three Clue Rule 作参考，不是铁律）；秘密与彩蛋可以只给一条，否则显得廉价。

**storylet：场景级内容单元**

- storylet 是骨架而不是文字：前提（Java 判断的状态）、处境、利害、可能的效果（白名单，由 Java 执行）；文字、对话与细节由 LLM 现场写。
- 状态只由 Java 掌握，LLM 只读和提议。每个 storylet 声明读写哪些状态，请求只附相关的世界事实（显著性驱动），以此代替携带完整历史（§5.6）。
- LLM 提议的新 NPC、地点、线索与 storylet 骨架，经校验后成为正史并存档，以后相关时再读出。世界越玩越厚，而不是越玩越漂。
- 组合：一个 storylet 是一个场景；几个串成一段小旅程（一个遗迹、一条支线）；小旅程通过共享状态（反复出现的 NPC、阵营关系、被改变的地点）拼成战役。
- 神谕：Java 先从随机表抽种子（如“背叛 × 古老契约”），LLM 围绕种子写，以此对抗模型的模式坍缩（参考 Ironsworn 的 Oracles）。

**世界层（2026-11-13 确认）**

- 没有预设的主线剧情。高自由度与固定主线互相冲突，改用威胁阵线（参考 Dungeon World 的 Fronts）提供方向与宏观叙事，分两级：
  - 战役阵线：一到两条贯穿全程的大冲突，带终末（没人阻止时会发生什么）与分布在全世界的征兆。
  - 冒险阵线：属于一个区域的本地威胁，带 3–5 个不祥征兆与时钟，不处理就按时推进。
- 开局预设若干“引发事件＋一到两条阵线”的组合；世界扩大时用神谕（Oracle）抽新阵线（如“亡灵 × 复仇”），阵线之间可相互影响。
- 世界设定（Truths，参考 Ironsworn）：开局定下几条基本事实（“旧神已死”），所有生成内容不得违背。另有反复出现的角色（宿敌的手下、立场摇摆的盟友），可选一个线索分散在多个区域的核心谜团。
- 连接规则：区域创建时至少与世界层有一条连接（本地阵线是某条战役阵线的爪牙、症状或争夺的资源；反复出现的角色登场；核心谜团的线索）。但不是每个区域都强关联：有些区域只有本地故事，作为喘息，否则显得刻意、世界显得太小。节奏要张弛有度。
- 区域结局反馈到世界：本地阵线被解决，对应的战役阵线受挫；被放任，它就推进一格。
- 宿命感来自伏笔先于回收：战役阵线的征兆与终末在开局定好，早期的小事（干涸的井、做同一个梦的村民）后来被证明是前兆。
- 阵线的作用是在玩家迷失时给出指引，不是逼玩家做什么：终末降临也不等于游戏结束，只是世界改变，故事在新世界里继续。
- 玩家自立的长期目标（Ironsworn 的史诗誓言）以后再考虑是否加入。

**区域内容：骨架先定，血肉随注意力生长（2026-11-13 确认）**

- 世界无尽，边缘随走随生成：玩家往没去过的方向走就生成新区域，不需要主线批准。爱四处逛的玩家一直在开新地图，爱清图的玩家可以把一个区域做完再走。不做玩家画像。
- 骨架在区域创建时由 Java 定下并存档，之后不变：有哪些地点、地标、遗迹，最多几个任务与秘密，有哪些阵线。秘密要先存在才能被发现，否则线索是事后补的，显得廉价也容易矛盾。
- 血肉跟着玩家的注意力生长：玩家追问、停留、反复交谈的对象，记为“玩家在意的东西”，以后生成时优先展开（即兴 GM 的“Yes, and”），任务从玩家的兴趣里长出来。模型也可以回答“这里没什么特别的”。
- 不用地图上的“？”标记：日志记的是角色听说过的事与未解的疑问，传闻可能不准或过时，要亲自去看。
- 收尾靠后果而不是打勾：每个区域有一份编年记录，写玩家在这里做了什么、这里因此变成了什么样。
- 生成端节流：已有 4 条游戏抛出、玩家还没碰过的钩子时，模型优先推进或回收已有的，不抛新的。这是给模型的节奏规则，不限制玩家接多少任务；N＝4 是基准，试玩后校准。
- 给回去的理由，防止滚动窗口：中心城有不可替代的功能（回满、交易、委托）；线索指回去过的地方；未处理的威胁会改变去过的地方，处理过的会留下后果。

**纪元与传说流（方向，2026-11-13）**

- 战役阵线有了结局（被阻止或终末降临），且玩家主动选择时，一个纪元结束；不因时钟走完强制结束。世界带着全部后果进入下一纪元，抽出新的战役阵线。战役按完整 RPG 的内容量设计（几十小时起），不是 roguelike 的短局。
- “传说流”（世界保留、上一代成为下一代的传说；业内叫 generational play 或 legacy，参考 Pendragon、Wildermyth、Dwarf Fortress）：前任的事迹、遗物、纪念碑与后代成为新纪元的内容。前任不会消失，可作为 NPC，甚至有限制地召回。
- 默认死亡不是永久的；以后可加硬核模式（永久死亡）。
- 默认继续同一角色（2026-11-13 确认）：纪元结束时世界前进几年、阵线换新，角色留下，上一纪元的事迹照样成为传说（NPC 讲的是玩家自己的故事）。换人传承是玩家主动的选择；只有硬核模式下死亡强制传承。

**尺度升级与爽感（方向，2026-11-13）**

- 参考玄幻网文的“换地图”：战役本身也是一个更大的“区域”，循环是清区域 → 开更大的地图 → 再清，一次比一次概念宏大、难度更高，直到力量体系的极限。尺度层级与 §4.1 的能力阶段（T0 普通人到 T5 以上，向上开放）对应。
- 逻辑相同，但要消除单调感：每升一级换掉风味与玩法，冲突规模从个人到势力、王国乃至更大，出现新的行动、新的社会角色；回到旧地图时被认出、被敬畏，是对成长的回报。
- 不追求处处平衡难度：重点是不无聊，而不是不让玩家变强。危险梯度保证想要挑战时往外走就有；回到低层区域时让玩家碾压，碾压要快、要有反应（NPC 的敬畏、名声），不拖成一场场必胜的战斗。
- 节奏用压力与释放：阵线制造逆境与压迫，逆袭时释放；逆境期可长可短，不是每段都必须有。
