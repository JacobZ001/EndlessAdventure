本文件是 [DESIGN.md](../DESIGN.md) 的 §7，章节编号沿用总文档，文中“§X.Y”跨文件通用（各章所在文件见 DESIGN 的模块索引）。术语见 DESIGN 术语表，计划与实现现状见 DESIGN §2。

## 7. 物品与预设内容

### 7.1 装备与背包

- **装备位（2026-10-18 确认）。** 主手、护甲、副手三格。主手放任意武器；副手放盾牌或轻武器（双持与副手攻击，§7.2）；双手武器装在主手并占住副手，副手须先清空，副手有物品时也不能装双手武器。单手与轻武器都可配盾。装备可授予特殊行动，首版内容每件一个，不设永久上限。
- **背包。** 不限容量，支持浏览与排序。战斗外换装与使用物品不增加冒险回合；战斗中用物品 2 AP。
- **定义与身份。** 手写与生成内容使用同一执行规则；获得时验证并保存完整定义，使用或读档不重新生成，效果变化必须是明确升级。物品须有可持久引用的定义 ID，不能只靠名称恢复。装备改变当前威力与可用行动，角色已获得的成长不因换装消失。

### 7.2 武器与护甲

- **武器两层（2026-10-18 确认，参考 D&D 2024 与 PF2e）。** **种类**是武器原型（长剑、钉锤、匕首、大剑等），写在代码中，各自固定基础值、一个缩放属性与零到多项武器特性；单双手与能否放副手也是特性（轻型、双手），不另设类别。**具体武器**（铁质长剑、士兵制式长剑、异教徒蛇牙剑等）是目录数据，只填名称、描述、种类与品质，v1 起可另带一个独有特殊行动或附魔。武器基础 = 种类基础 × 品质阶（普通 1／精良 2／大师 3／传奇 4）。种类基础按参考区间设定：轻型约 3、单手约 6、双手约 9（对应原类别系数 0.5／1／1.5），带强特性的种类可下调、无特性的可上调，试玩后按种类单独校准；数值由 Java 中的种类表给出，数据文件与生成内容只能选种类与品质，不能自定数值。同为单手（或同为轻型）的种类之间靠基础、缩放属性与特性区分用法。
- **护甲**分轻／中／重：护甲 = 类别基础（轻 2／中 4／重 6）× 品质阶（与武器同一组品质阶，普通 1 至传奇 4），即普通 2／4／6、传奇 8／16／24。重甲带潜行减值与移速 −1。盾牌值 = 2 × 品质阶，在举盾时增加 G（§6.2）。护甲没有种类这一层。
- **v0 武器（2026-10-18 确认）。** 只做近战。种类（基础为普通品质，括号内为缩放属性与特性）：长剑 6（STR；多用，双手持握 8）、钉锤 6（STR；穿透）、弯刀 6（DEX）、大剑 9（STR；双手、破防）、短剑 3（DEX；轻型、致命）、匕首 3（DEX；轻型、刺杀）。具体武器每个种类可有多件（AI 生成目录数据，便于比对，README 注明），起始装备只从普通品质中选。武器面板显示种类、品质、缩放属性、基础值与特性；特性效果在攻击预览中写明（如“破防：无视防御 3”）。远程须先定贴身时的规则，随 v1 加入。
- **武器特性（Weapon Property，与角色特质无关）。** 一个种类可带多项特性；类别给出适合的特性池。重武器靠直接高伤害，轻武器靠条件触发与命中效果，低威力武器打不穿重甲属合理。v0 的特性全部为确定性规则：
  - **轻型（Light）：** 可放副手（双持）。**双手（Two-Handed）：** 占住副手。两者互斥，也都不与多用同时出现，由种类表在启动时校验。
  - **多用（Versatile）：** 副手为空时双手持握，基础增加同品质盾牌值（2 × 品质阶，普通长剑 6 → 8）。等于放弃盾牌、把它的价值换成输出：剑盾防御时每次少挨 2，双手持握每击多打 2；仍低于大剑（9 且有破防）。若只加 1 × 品质阶，每击多 1 却在防御时少 2，严格劣于配盾。
  - **穿透（Pierce）：** 本次攻击的 Pen = 2 × 武器品质阶（普通 2），降低目标有效护甲（§6.2）。
  - **破防（Break Guard）：** 攻击正在防御的目标时无视其 G。
  - **致命（Lethal）：** 目标 HP 不高于一半时暴击。
  - **刺杀（Assassinate）：** 目标本场尚未行动时暴击，配合先攻与伏击。
  - **暴击：** 原始伤害翻倍（扣护甲前）。v0 条件满足即必定暴击；是否加入命中随机与暴击率随 v1 再定。
  - 延后：连击（普攻分两次命中，各自扣护甲并各施加命中效果，依赖状态系统）、投掷等。
- **双持与副手攻击（v0）。** 副手持轻武器时可用“副手攻击”（§6.1）：1 AP，须本回合已用主手普攻；原始伤害 = 副手武器基础＋近战技能，不加属性（参考 D&D 副手攻击不加属性调整值），单独扣一次护甲；副手武器的特性不生效。双持不能举盾。普攻剩下的 1 AP 由此有三种用法：防御（剑盾，承伤 −5）、副手攻击（T1 短剑对站定防御的强盗 11−7＝4，对未防御 7）、走位；用副手攻击的回合没有防御，对方一击从 9 升到 14。
- T1 对强盗验算（站定防御时护甲＋G＝7）：大剑每击 14（对防御中的目标 17），3 击；长剑配盾 11，4 击；长剑双手持握 Q 20，每击 13；钉锤 Q 18、穿透 2，每击 13；短剑（致命）8、8、8 后强盗降到半血以下，第 4 击 15×2−7＝23 击倒，共 4 击；匕首（刺杀）若先于强盗行动，首击 15×2−7＝23。
- “开局用短剑刺杀，下回合换大剑输出”这类打法是否允许，取决于战斗中能否切换武器及成本，随 v1 决定。

### 7.3 预设内容与数据文件

- **预设目录。** 生成装备与特殊行动延后，首版先有预设目录：先定义物品、特殊行动、敌人的模板字段与各等级的数值区间，具体条目由 AI 离线生成为数据文件，Java 读取时按区间校验，README 注明 AI 生成的数据。首版目录：每种缩放属性至少一把近战或远程武器、轻／中／重护甲、盾、恢复药水、约三个特殊行动、一到两种敌人模板。战利品由 LLM 从目录中选择 ID，Java 校验。
- **格式：Gson 读取 JSON。** 敌人模板等嵌套数据若用 Properties，要写成带索引的扁平键并为每类数据手写解析循环，AI 生成也容易写错序号；Gson 把 JSON 直接映射到 Java record，文件结构与类定义一一对应。版本 2.13.2 或更新（修复了 Eclipse 认不出模块名的问题），运行时只需这一个 jar。
- **结构。** 数据定义集中在一个包（如 `com.endlessadventure.data`），每类一个文件（`weapons.json`、`armor.json`、`enemies.json` 等）对应各自的 record，不做多态反序列化；启动时由一个目录类读入并按 ID 建索引，由 Driver 创建后传给 GameEngine。运行时对象按 ID 引用定义，存档只保存定义 ID；现有 `Item` 的进程内自增 ID 须改为定义 ID。
- **校验。** Gson 对缺失字段填 null 或 0、忽略未知字段、把未知枚举值变成 null，都不报错；Gson 创建普通类对象时又会绕过构造函数，因此 JSON 先读入目录类内部的私有 record，再调用游戏类（`Weapon` 等）的构造函数建对象，必填字段与数值区间只在构造函数中检查，出错时连同文件名报启动错误。被 Gson 读取的包（数据包，以及枚举所在的 `entity`、`inventory`）须在 `module-info` 中 `opens` 给 `com.google.gson`，否则读取报错。
- 存档继续用 Properties，LLM 剧情协议继续用 key=value。
