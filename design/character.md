# Endless Adventure 设计：角色、检定与自由行动

本文件是 [DESIGN.md](../DESIGN.md) 的 §3、§4，章节编号沿用总文档，文中“§X.Y”跨文件通用（各章所在文件见 DESIGN 的模块索引）。术语见 DESIGN 术语表，计划与实现现状见 DESIGN §2。

## 3. 角色

### 3.1 属性

| 属性 | 能力范围 | 战斗中的作用 |
|---|---|---|
| 力量 STR | 施加身体力量、克服外部阻力 | 施力型攻击、推动与挣脱；不自动增加所有攻击伤害 |
| 敏捷 DEX | 协调、平衡与精细动作控制 | 精细操控型攻击、闪避的躲开判定；不提高 AP、移速或普攻次数 |
| 体质 CON | 健康、承受负荷与持续活动 | 额外 HP、肉体抵抗、以体质缩放的特殊行动 |
| 智力 INT | 推理、理解结构、运用知识 | 依赖分析与知识的特殊行动（含法术）；不统一增加法术威力 |
| 察觉 PER | 捕捉环境与行为线索；不自动得知隐藏事实 | 默认先攻、瞄准等有明确规则的行动 |
| 意志 WIL | 在干扰与压力下维持控制与专注 | 精神抵抗、专注、意志驱动的能力 |
| 魅力 CHA | 表达、感染力与人际影响；不等于外貌或声望 | 影响、诱导等表达驱动的能力；社交成功不等于任意控制敌人 |

- 不设 Endurance，DEX 不拆分；当生命耐久与行动续航、或机动与精准操作各自成为需要分别投入的构筑时再重评。
- 属性可成长至超人级，超常表现不全部依赖装备、魔法或特质。
- 长期属性、派生数值与当前资源分开：最大 HP 由等级与体质派生，当前 HP 独立变化。
- 属性与技能属于所有角色，包括不参战的 NPC（对话与互动也会触发检定）。
- AP、移速、反应次数与共享资源恢复不随属性普遍增长，特定构筑以后可通过明确能力改变。
- 已知局限：首版没有可执行战斗行动的属性（v0 的 INT、WIL、CHA 等），其战斗构筑收益尚未兑现。

### 3.2 技能

| 战斗技能 | 默认属性 | 范围与边界 |
|---|---|---|
| 近战 | STR | 近身武器及徒手攻防；缩放属性由具体武器或特殊行动规定，不逐种武器设独立等级 |
| 远程 | DEX | 射击与投掷武器，也可射断绳索等非战斗目标；单纯用力投掷物体不算武器操作 |
| 施法 | INT | 执行已掌握的魔法能力，缩放属性由能力规定；不自动授予法术或全部魔法知识 |

| 通用技能 | 默认属性 | 范围与边界 |
|---|---|---|
| 运动 | STR | 攀爬、游泳、搬运、推拉等施力或持续运动 |
| 身法 | DEX | 平衡、翻越、落地与全身协调；与精细手部操作分开 |
| 潜行 | DEX | 隐藏自己、安静接近与避开注意；不包含偷取随身物品 |
| 巧手 | DEX | 隐蔽取物、藏物、开锁与精细操作；工具和结构知识前提仍然有效 |
| 侦察 | PER | 搜寻、警戒、监视与发现环境线索 |
| 调查 | INT | 整理证据、分析结构与因果、重建经过；不提供缺失的专业知识 |
| 洞察 | PER | 理解情绪、动机与行为模式；不是读心 |
| 生存 | PER | 导航、追踪、觅食、营地选择与野外应对；侧重实践 |
| 医疗 | PER | 诊察、急救、处理伤势与毒素；具体治疗须有对应规则 |
| 驯养 | PER | 训练指令、日常引导与配合的实践；不作为全部非人交互的总技能 |
| 说服 | CHA | 以理由、利益或情感争取自愿合作；请求条件仍有效 |
| 欺骗 | CHA | 编造、隐瞒与维持虚假印象；不能让不可能的说法成为事实 |
| 威吓 | WIL | 以可信威胁或威势迫使让步 |
| 表演 | CHA | 演奏、演说、扮演与吸引注意 |
| 历史 | INT | 历史、文化、组织与制度知识 |
| 自然 | INT | 物种、生态、地形与自然现象知识；知道原理不等于具备野外操作能力 |
| 宗教 | INT | 信仰传统、仪式、教义与宗教组织知识；不授予神术 |
| 奥秘 | INT | 魔法原理、符文与超自然现象知识；识别法术与施放法术分别判断 |

- **默认属性**用于界面显示、LLM 提示与未指定手法时的默认选择；实际检定按手法选属性（威吓也可用 STR 或 CHA）。各属性挂的技能数不均匀属正常，属性价值按技能、战斗与抵抗的总和评价（CON 提供 HP 与肉体抵抗，WIL 提供精神抵抗与专注）。威吓默认 WIL，因为 WIL 定义为在压力下维持控制。
- 分组只用于浏览与成长预算，不共享组级加值，不限制使用场景（远程可用于探索，洞察可支持战术行动）。
- 一次目标只用一项主要技能，研究与实际应用不连续检定。奥秘与施法分别表达理解与执行，使用已学法术不检定两次。
- 防御、专注、毒素抵抗等不设技能，由属性与派生数值承担。
- 技能正式纳入前须有清楚的典型用途、适用条件与实际收益；只有换措辞效果的低频项应补充内容或推迟开放。LLM 不能临时创造技能项。制作、修理与附魔等有规则后再加入。

### 3.3 特质、专长与知识

**特质（执行原则）。**

- 玩家与 NPC 用相同规则；背景、训练、血脉、种族、祝福等来源不各建一套效果规则。名称、来历与适用领域可由 LLM 生成，机械效果须组合已实现的能力与规则。
- 特质可提供被动修正、授予特殊行动或受支持的条件效果，只在少量共同位置结算：检定读取修正，可用行动汇总已授予的特殊行动，确有需要时再为伤害或回合结算加入条件效果（时机、条件、效果、次数或期限）；不在各处检查具体特质名称。
- 效果定义与持有者的使用状态分开，冷却、剩余次数和持续时间各自记录。移除或到期只撤销该来源；临时复制或变身结束不能靠恢复旧状态撤销已受的伤害；触发效果须明确顺序、叠加与次数，避免循环。自然语言不能赋予未实现的语义，模型输出不作为代码运行。
- 技能不自动授予该领域所有特殊行动，普通行动也不必先解锁；角色已学的特殊行动与装备临时授予的分开判断。
- **多面手（方向）。** 给想走通才路线的玩家：低于 4n 的技能在检定中按 4n 计算，使没投入的能力维持在低一阶段左右，代价是占一个特质位置；参考 PF2e 的 Untrained Improvisation。它修改技能的有效值，须等“v1 特质不修改核心数值”的限制放开后再加入，数值届时校准。
- 最小验证：属性修正、专长检定修正、授予一个特殊行动、一个受限条件特质；同一定义能被玩家与 NPC 正确使用、状态互不干扰。首次不做复制与变身。
- 工程参考：[Riot 塞拉斯技能封装](https://www.leagueoflegends.com/en-us/news/dev/origins-sylas/)、[Riot 梅尔反射](https://www.riotgames.com/en/news/mel-reflect-tech-blog)、[Unreal Gameplay Ability System](https://dev.epicgames.com/documentation/en-us/unreal-engine/using-gameplay-abilities-in-unreal-engine)。

**专长与缺陷。** 专长表示对某个子领域（特定对象、风格、环境或操作）的深入经验，缺陷是其反面。

- 取得时写明适用的技能，可以多项、可跨战斗与通用技能；之后固定，LLM 不能临时扩大。
- 检定时由 LLM 提出适用的专长，并说明情境为何落在其子领域内，玩家可见；Java 只校验所用技能在该专长的列表内，不按技能自动套用。
- 专长固定 +4、缺陷固定 −4，同一次检定最多取一个专长。
- **建议：**适用技能不超过 3 项。
- 上下位、重叠或近义专长不叠加，措辞更窄不提高加值。玩家自称熟悉某主题不直接获得专长，孤立事实进入知识记录。
- 专长不定义伤害倍率、新行动或资源效果；没有检定的战斗行动不把专长折算成伤害。

**知识与线索（方向）。**

- 知识记录角色实际获知的见闻、证据与说法：一份记录加少量多选关联（任务线、地点、人物、主题），不建完整分类树。任务日志按关联展示线索，任务结束不抹除知识。
- 世界事实与角色所知分开，玩家的知识不自动共享给 NPC。
- 一般问题按通识与技能处理；深入问题结合经验、资料、工具与研究过程。没有接触途径的唯一秘密不能靠高数值获知；已记录的事实无需重新检定；传闻保留来源，不视为客观真相；资料、协助与研究时间可替代缺少的专长。

### 3.4 创角与成长

| 项目 | 规则 |
|---|---|
| 创角 | 七属性起始 0、预算 8、单项上限 4，不允许负值；战斗技能预算 8、单项上限 8；通用技能预算 12、单项上限 8；三组点数须恰好用完 |
| 暂无内容的技能 | 远程（v1 才有远程武器）与施法（首版没有法术）照常可发点，创角界面在旁注明“暂无内容”；投在这两项的点会使普攻威力低于设计基线（基线按近战 8 点），v1 可用重新分配挪回（2026-10-22 确认）。施法是否在有法术之前就开放发点，v1 再定 |
| 背景（v1） | 2 个专长、1 个缺陷；可自拟或随机，提供与世界一致的已知信息，不默认解答后续秘密；背景文字不能绕过取得规则 |
| 升级 | 属性点在 3、5、7……级各 +1；战斗技能每级 +1；通用技能每级 +2 |
| 技能单项上限 | min(7＋L, 8 × 阶段(最高属性))，阶段(a) = max(3, ⌈a/4⌉) |
| 读档 | 只检查不超过当前等级的上限，允许有未分配的点数 |
| 重新分配（v1） | 在安全地点花一个冒险回合，可重新分配全部属性点与技能点；按同样的预算与上限校验，背景专长与缺陷不变 |

- **属性与技能 1:2。** 典型 TN 角色属性 4n、技能 8n（C＝12n）。起步专攻为属性 4＋技能 8＝T1；17 级典型属性 12，人类上限 T3 为属性 12＋技能 24，属性超过 12 即超人。专业能力主要来自技能，属性还影响多项检定与派生数值。
- **每阶段 8 级。** 专攻能力每级约 +7.5 个百分点：约 9 级进入 T2、17 级到达 T3、25 级进入 T4，等级不封顶（5、6 级一阶段跳动过大，12 级成长过慢）。
- **超越人类极限。** 最高属性 ≤ 12 时技能上限最多 24，与 7＋L 一致；进入 T4（13–16）后放宽到 32，T5（17–20）为 40。上限只在分配点数与读档时校验，不影响检定与攻击计算。技能不绑定单一属性，故以最高属性为准，检定仍按实际所用属性。凡人单项技艺超越人类极限由专长或其他特质提供检定修正，不与属性系统相交；绝对力量的可行性（如抬 300 kg 闸门）属前提判断，技能不能抵消巨大的力量差距。
- **专精宽度与锁定（2026-10-14 分析）。** 每级点数恰好等于上限增长（技能上限每级 +1，战斗技能点每级 +1，通用技能点每级 +2），所以任何等级下玩家只能维持 1 项主属性、1 项战斗技能、约 2 项通用技能跟上当前阶段，其余停在 T0 附近，分散投入只会样样不够用。这比 D&D 5e（4–8 项熟练技能随等级一起涨）和 PF2e（受训技能含等级加值）都窄，天然依赖队友分工；数值随等级线性增长，加成有上限，不会膨胀。
  - 没投入的检定只靠属性：用主属性（4n）做低一阶段的中档挑战，T1 时 95%、T2 时 55%、T3 时 15%、T4 时 0%；区域强度不随玩家缩放，越往后越明显。PF2e 的难度同样陡，所以有 Untrained Improvisation 专长；D&D 的难度不随等级上涨，没投入的技能一直勉强可用。
  - 真正的问题是锁定：新起步的技能每级只能分到与上限增长相同的点数，起步差距永远不会缩小，中途换路线（如近战改远程）永远追不上。因此加入**重新分配**（v1，见上表；参考 PF2e 的 Retraining 与《博德之门3》营地重置），总预算不变，不造成膨胀，可复用 `Player.Builder` 的校验。
  - 想走通才路线的玩家以后可取“多面手”特质（§3.3）；不把它设为所有人的默认，以免冲淡专精与队友的价值。首版是单人游戏，通用技能维持每级 +2；加入 NPC 队友后再评估是否降到每级 +1。
- **弱项。** 没投入的能力停在 T0。缺陷的结构与专长相同（§3.3），相关检定 −4；不补偿点数，主要提供风味与叙事（如“怕龙”），不要求触发频率。不采用负属性换点。弱项应尽量留下耗时、资源、风险或路线不同的替代方案；统一预算只是最小约束，不能替代强度平衡。
- **成长来源。** 升级提供等级派生的 HP 与 G、两组技能点和属性点。冒险里程碑（LLM 提议、Java 校验）提供特质（含专长）、特殊行动与知识，不直接发技能点或属性点；特质附带的修正作为可撤销来源记录；v1 特质不修改属性、技能等核心数值，试玩后再定。装备提供武器基础、护甲与授予的特殊行动，卸下即失去。剧情中的训练与研习属于里程碑，不能靠重复输入刷成长。
- **经验。** 以目标经验为主：完成情境目标时发放，不论方法，同一目标只发一次；目标及经验档由 LLM 提出、Java 校验保存。战斗经验不打折但小于目标经验，远低于玩家等级的敌人经验衰减。战斗独有收益是战利品与永久清除威胁，避战独有收益是保住 HP、资源与时间以及情报或关系；纯避战路线的成长速度不低于全清路线的一定比例。参考 Bloodlines、Pillars of Eternity、Deus Ex: Human Revolution、Baldur's Gate 3。
- **奖励。** EXP 按本级进度保存，获得后处理溢出与连续升级。奖励资格由 Java 决定，模型不能直接指定等级或 EXP；敌人基础奖励开战时固定，低 HP、卸装备等不提高奖励。剧情奖励与里程碑须检查间隔与重复领取（候选：每次剧情最多一件物品、间隔至少 3 回合；小／大里程碑间隔 3／10 回合，奖励为基准的 0.5／2 倍）。
- **种族。** 首版不做种族选择，种族只作背景叙述。以后种族不改属性、移速与 HP（参考 D&D 2024），机制收益固定为一个种族特质，强度与背景专长同档（如矮人“石工专长 +4”），各种族数量相同；暗视等待光照规则落地后再提供。

### 3.5 派生数值

成长单位 n = (7＋L)/8：1 级为 1，每过一个阶段（8 级）+1。按 n 定义的数值取四舍五入的 X·n，即整数运算 (X·(7＋L)＋4)/8（如简单防御 3n、敌人 HP 42n）。数值尽量以“每阶段多少”定义，平衡调整只改每阶段的值。战斗数值全部为整数。

| 数值 | 规则 |
|---|---|
| 玩家最大 HP | 18×(7＋L)＋8×CON＋明确加成；按当前状态计算，不存档（存档只存当前 HP） |
| 当前 HP | 升级与 CON 提升时增加与最大 HP 相同的量，不回满；首版没有降低最大 HP 的来源 |
| 普攻威力 Q | 武器基础＋武器声明的属性＋对应战斗技能＋明确修正，原值相加；徒手的武器基础为 0，用 STR＋近战 |
| 简单防御 g(L) | 3n（三种防御见 §6.2） |
| 对抗抵抗 D | 防守属性＋等级＋11（§4.1） |

- 最大 HP 只依赖当前等级与体质，投入时点不造成永久差额（体质约 4n 随等级线性增长，“等级 × 体质”会平方增长）。专投体质各阶段约多 22% HP；1 点 CON 换 8 HP 与 1 点 STR 换 1 点 Q 大致相当。
- 每把武器只声明一个缩放属性，不临时取最高属性。

## 4. 检定与自由行动

### 4.1 检定

能力阶段是评分刻度，用于给挑战定档和描述角色水平，玩家看不到。

| 阶段 | 含义 | 例子 |
|---|---|---|
| T0 普通人 | 没受过训练的普通成年人 | 普通人爬墙、撬简单的锁 |
| T1 合格 | 受过训练的从业者 | 普通士兵、熟练锁匠 |
| T2 精英 | 一城之内的佼佼者 | 卫队长、名医 |
| T3 大师 | 一国顶尖，人类极限 | 传奇剑客 |
| T4 超人 | 超出人类极限 | 徒手抬起 300 kg 闸门 |
| T5 及以上 | 神话级，向上开放 | 以后再定 |

每个阶段分低／中／高三个子档。“TN 中档”指 TN 阶段的人能胜任，成功率 75%；子档之间相差 20 个百分点，阶段之间相差 60 个百分点。

| TN 阶段的人面对 | 成功率 |
|---|---|
| 低一阶段的任何挑战 | 100% |
| 本阶段低档／中档／高档 | 95%／75%／55% |
| 高一阶段低档／中档／高档 | 35%／15%／0% |
| 高两阶段 | 0% |

- **行动组合。** 一次行动采用一个适用属性、一项适用技能，至多一个专长。玩家选择目标与实际手法，LLM 提出组合与条件，Java 校验后结算。同一技能可因手法采用不同属性，同一目标也可经不同技能达成；改写措辞不算新手法或重试机会。已学特殊行动与装备能力在定义时固定允许的缩放方式，不由 LLM 临时改写。
- **公式。** P = clamp(75% + 5% × (C − D), 0, 1)，C = 属性＋技能＋专长与情境修正。环境挑战的 D 由难度档换算：TN 低／中／高档 = 12n − 4／12n／12n + 4。
- **对抗抵抗。** D = 防守属性＋等级＋11（基础 7，等级视作一项练满的技能，再按高档 +4；同阶段典型防守者约 55%）。防守属性由效果定义时声明，可多选一（强制位移可用 STR 抗或 DEX 躲，幻象可用 INT 识破或 WIL 抵御），程序取防守者在声明选项中的较高值；LLM 或玩家不能在声明范围外挑选。
- **修正。** 专长 +4、缺陷 −4、协助 +4。同一挑战只一人尝试，其他人可协助，不允许每人各掷一次。同类修正只取最高，不同类相加；工具或装备的检定加成上限 +4，专长与装备合计最多 +8。状态、工具、环境等情境修正可在此之上加减。
- **原则。** 先校验前提再谈概率；安全且熟练的日常行为直接成功；不设全局 5%／95% 封顶；同一已知挑战的难度不随玩家升级而变；LLM 提出方法与难度档，Java 计算并只掷一次；显示精度与判定一致；必要时展示玩家一方的主要贡献，不展示阻力；不把一次尝试拆成多个独立门槛。攻击伤害稳定结算；命中随机只来自闪避与暴击（§6.2、§7.2），不加入多级成功。
- **取舍。** 线性映射到 0% 或 100% 后加点不再改变该挑战的成功率，不采用 S 曲线。D&D 2024、PF2e、GURPS 的同级胜任率约 55%–74%；单人游戏失败代价明确，故取偏高值。

### 4.2 自由行动（流程）

自由输入由 LLM 归为四类：

| 类别 | 处理 |
|---|---|
| 直接叙述 | 安全的日常行为，无检定，直接续写 |
| 需要检定 | LLM 提出方法（一个属性、一项技能、至多一个专长）、难度档、成功结果与失败代价；Java 校验方法，换算 D 并计算成功率；确认前显示方法、成功率、风险标签与失败代价，玩家可确认或换用其他合法方法；确认后只掷一次，再由 LLM 按结果续写 |
| 当前不可行 | 缺少前提时说明原因，不收费、不推进回合 |
| 切换模式 | 战斗、对话、休息等 |

- 是否需要检定并入现有续写请求：直接叙述仍为一次调用，需检定为两次。
- 难度：LLM 只选挑战本身的难度档（§4.1 的阶段与子档），Java 换算为 D，再按成功率给出风险标签 guaranteed／easy／normal／hard／impossible（normal 居中）。玩家只看到成功率与风险标签，看不到难度档或 D。
- 已知挑战及其难度保存在情境中，不重新定档。重试须有方法、条件或成本的实际变化；已结算行动的随机结果不因改写措辞、叙述重试或读档而重算。
- 失败代价暂取白名单：时间流逝、惊动敌人、机会关闭、有上限的 HP 损失，由 Java 限定上限并在确认前展示。成功结果以叙事和信息为主，机械奖励走奖励规则。
- “当前不可行”只用于缺少前提；能力不足仍是检定，以低成功率和 impossible 表达。理由从固定类别中选：缺少所需物品或工具、目标不在场、未掌握所需能力、违反玩家已知的世界事实；前三类由 Java 对照背包、情境角色与已学能力核实，不符则按检定或直接叙述处理。依赖玩家未知的隐藏事实（如“这里没有暗门”）时不能免费告知，应作为有时间成本的世界内尝试。
- **生物交互。** 按实际手法、可用沟通方式和对象的理解与行为条件判断，不按人类与非人类一刀切：会谈判的龙可以被说服，不理解承诺的动物不能靠语言交易，没有恐惧反应的目标不会因威吓退让。不同生物的经验不自动等价；熟悉对象可提供方法、信息或有界的情境优势，不熟悉也不禁止观察、试探或学习。
